# 文档索引

> 这套文档只描述**本仓库当前的代码**。每条结论都应能回到源码；无法从代码确认的点会显式标注"待验证"。

## 这套文档回答什么

1. **它怎么工作**：进程模型、启动顺序、登录与代理的数据流。
2. **契约是什么**：HTTP 路由、IPC 命令与事件、兼容网关的端点、`settings.json` 的键、数据库表。
3. **坏了怎么查**：日志在哪、状态码含义、常见故障的定位顺序。
4. **怎么改**：门禁命令、测试布局、文档与代码的对账规则。

## 建议阅读顺序

- **第一次接触**：根目录 [README.zh-CN.md](../README.zh-CN.md) → 总体架构 → 本地代理。
- **接了客户端但跑不通**：本地代理 → 网关契约 → 排障手册。
- **数字对不上**：用量统计 → 本地代理（看落库时机）。
- **登录/续期异常**：认证与凭据 → 排障手册。
- **要改代码**：总体架构 → 开发与构建 → IPC 接口。
- **验签 / 签名政策**：代码签名政策（含申请状态、产物配置与隐私声明）。

## 文档约定

| 约定 | 说明 |
|---|---|
| 语言 | 正文中文；命令、路径、字段名、错误串保持英文并用反引号 |
| 事实口径 | 以代码与测试为准。仓库里不引用外部部署地址、公司或个人信息 |
| 不确定项 | 显式写"（待验证）"，不猜测 |
| 源码索引 | 每篇文末列出该文依赖的源码文件 |
| 清单块 | 需要与代码对账的列表用 ` ```text name=xxx ` 代码块给出，由门禁脚本逐项比较 |
| 链接 | 相对链接必须指向版本库内的真实文件 |

## 文档与代码的对账点

`node scripts/check-public-repo.mjs`（`pnpm docs:check`）会检查下列清单块与代码是否完全一致，任何一侧多出或缺少都会让 CI 失败：

| 文档 | 清单块 | 代码来源 |
|---|---|---|
| [ipc-api.md](ipc-api.md) | `ipc-commands` | `src-tauri/src/lib.rs` 的 `generate_handler!` |
| [ipc-api.md](ipc-api.md) | `ipc-events` | `src/lib/events.ts` 的 `AppEventName` |
| [settings.md](settings.md) | `settings-keys` | `src-tauri/src/settings.rs` 的 `Settings` |
| [data-model.md](data-model.md) | `db-tables` | `src-tauri/migrations/*.sql` |
| [proxy.md](proxy.md) | `proxy-routes` | `src-tauri/src/proxy/routes/mod.rs` |

同一个脚本还会扫描敏感信息（内网地址、公司/部门名、个人账号、本机绝对路径、来源说明用语）并校验 Markdown 相对链接。

## 修改文档的规矩

1. 改行为 → 同步改对应文档；只改代码不改文档会被门禁或评审拦下。
2. 新增命令 / 路由 / 设置键 / 表 → 同步更新对应清单块（顺序不限，但条目必须完全一致）。
3. 不要写具体部署地址、账号、密钥或本机路径；示例统一用 `https://api.example.com`、`alice`、`%USERPROFILE%`。
4. 新增一篇文档时，回到本页把它加进地图与阅读顺序。
